# Phase 3 component validation

Run `bash scripts/phase3/run.sh` after Phase0/1/2 dependencies. It uses the original common Menagerie plant, Phase1 body/TCP/residual conventions and Phase2's 4ms command adapter. It does not use mj_geomDistance or any controller collision-distance constraint. Root-owned CAD/inspection_scene and scene_feasibility work is untouched. Contact-free initial configuration screening is not collision safety certification; independent Coal/FCL validation remains required before Phase4 distance constraints.

The Eigen-only library adds exact unregularized SVD-rank projector P=I-Jdagger J, evaluated as I-V_r V_r^T for stability. This is mathematically equivalent at the configured thresholded numerical rank. Singular values below the relative cutoff are treated as rank loss; JP leakage may be of that cutoff order rather than exactly zero for truncated nonzero values. Positive-damping P_lambda=I-J_dls#J is diagnostic only and is never used as the controller projector. DLS primary is supported via external primary_method=dls and uses Phase2's chosen lambda0.003; all canonical Phase3 runs use primary_method=mp. Regardless of primary, the secondary projector is exact MP. No optional DLS-primary execution result is claimed.

Joint cost H=sum(((q-mid)/range)^2), gradient=2(q-mid)/range^2 uses externally supplied common limits. Secondary policies: joint centering (-gradH), sigma_min ascent, regularized log-volume ascent, and combined joint/sigma ascent. Exact P applies after combining external scalar weights. Regularized log-volume=sum(log(hypot(sigma,epsilon))) is not log(sigma_min) and does not guarantee improving the weakest singular value. Indicators use SVD product, log product, regularized log-volume, sigma_min/max, condition, rank and simple-min gap, with both unscaled mixed units and scaled [linear;0.3m/rad*angular] raw J. No determinants are used. Tall underactuated matrices pad task singular values with zero. At exact rank loss condition/log-product may be infinite; regularized log-volume remains finite.

Singularity gradients are model-independent callback central differences h=1e-6, 15 Jacobian/SVD evaluations for7 joints, timed explicitly. sigma_min differentiability requires a simple smallest singular value and away-from-rank-loss neighborhood; simple_min/near_rank/min_gap flags include all perturbations. Flagged derivatives remain recorded and are not silently claimed valid. An independent directional check h=3e-6 validates 2000 FR3 configurations; absolute error gates near-zero derivatives, relative errors use1e-8 denominator floor and are still reported. Six unit cases include repeated-min and finite-overflow rejection checks; exact branch/rank differentiability is not claimed.

The numerical validator additionally checks2000 random6x7 matrices, injecting exact and almost rank-deficient cases, for exact leakage/symmetry/idempotency and damped leakage/idempotency contrast. It tests analytic joint-gradient differences and projected finite-step descent at2000 random valid URDF joint coordinates. These are mathematical samples, not independent controller trials.

config/phase3.yaml is frozen before numerical/development results. New development seeds41011/41012 and evaluation seeds51011/51012 select joint-limit posture (99% H_joint quantile) and singularity (0.1% sigma_min quantile) from20000 valid random configurations per seed, with2% bounds margin and initial contact screen. Each scenario includes a held pose and a0.02rad smooth feasible joint-derived closed path,4s plus2s hold after1s warmup. Primary-only baseline and all secondary methods share the same gain source, initial pose, plant, guard and task correction. Baseline has no secondary parameter. Each of4 secondary objectives gets exactly3 scalar gains [0.25,1,4], equally evaluated on8 development scenarios (24 trials/objective), then1 selected gain on8 held-out scenarios.104 development and40 evaluation trials. External weights joint1, sigma20, log-volume0.05 reflect distinct objective units, are fixed before results and not retuned. Feedback4/s and optional DLS lambda0.003 retain Phase2 provenance.

Gain selection uses the same frozen score for every objective:10*(mean position+0.3*mean rotation)+(final H-initial H)-log((final sigma+0.01)/(initial sigma+0.01))+0.001*mean accepted dq norm+0.01*intervention fraction+100*failure. This is a declared component tuning criterion, not a research-performance metric. No held-out retuning or forced favorable conclusion is allowed.

CSV records raw unscaled/scaled J P z leakage, guard-induced task distortion J*(accepted-requested_total), and postguard task difference J*(accepted-primary). These have different meanings; the guard term includes any primary clipping as well. q_before is the state for singular indicators/H/gradients/leakage; time_after/actual TCP/executed q,dq and pose errors refer to post-step state. Target integrator and measured state remain separate. All normalized per-joint margins and minimum radian margin are recorded. Runtime is controller computation excluding plant stepping/CSV writing, measured on WSL, with gradient cost/number of evaluations and4ms overruns; it is not a hardware real-time guarantee.

Codes COMPLETED/POSE_TOLERANCE_FAILURE/EXECUTED_LIMIT_VIOLATION refer to broad component execution tolerances, not final research task success. Exceptions retain raw error files and failure rows; output streams check writes/flushes. Runtime/clock columns are nondeterministic and must be excluded from byte-identical scientific replay comparisons. Offline audit uses NumPy and independently parses official URDF FK/axes instead of calling Pinocchio; all raw rows get guard/state/objective/pose checks, while every50th row independently recomputes J/projector/leakage/SVD and FK. Ill-conditioned projector comparisons are flagged rather than falsely asserted equal.

Execution may still lose pose accuracy or exceed measured velocity despite exact raw null-space leakage, due to limiting, finite-step/dynamic effects or multiple-objective tradeoffs. All unfavorable trials must remain in review/raw data. No acceleration/jerk/stale-state/collision constraints, CAD/payload, predictive/retiming/nullspace-research superiority or hardware claims are supported. Phase4 requires root Phase3 gate and independent collision-query validation.

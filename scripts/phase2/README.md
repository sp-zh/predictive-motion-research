# Phase 2 differential IK baselines

Run `bash scripts/phase2/run.sh` with the Phase 0/1 installed dependencies and pinned model checkouts. The C++ runner takes robot YAML, scene XML and experiment YAML paths; the mathematical library only depends on Eigen. `BUILD_BENCHMARKS=OFF` excludes the Pinocchio/MuJoCo runner dependencies from CMake. Package metadata includes runner build dependencies; core headers/source have no ROS, Pinocchio, robot names or mjData coupling.

Moore-Penrose uses a configured relative SVD rank threshold (sigma > tolerance*sigma_max and >0). DLS uses sigma/(sigma^2+lambda^2), with a stable scaled evaluation. Lambda=0 dispatches to the thresholded inverse. Adaptive damping is lambda_max*sqrt(max(0,1-(sigma_min/threshold)^2)); its lambda_max receives the same full candidate budget as fixed damping. Invalid shapes, finite values, rank tolerance, damping and method enum are checked. Exact rank deficiency produces a finite truncated MP answer, with infinite condition as a diagnostic; no infinite-motion claim is made.

The frozen design uses 0.3m/rad scaling of angular Jacobian/twist rows, 4ms control, SE3 residual e=log(T^-1 Td), and a validated body-coordinate residual Jacobian. Solve A*dq=K*e+B*desired_body_twist, with A=-J_e and B=Jlog6(E). Scaling is applied equally to A and the right hand side. Mixed row norms depend on this scaling and are not physical position errors. Velocity source is the generated official URDF; the run script verifies values against joint attributes before execution. Position limits intersect URDF, plant joint and actuator target limits.

Scaling is explicitly [linear; L*angular], L=0.3m/rad. Singular values and damping use the resulting Jacobian scale (m/rad for revolute joint columns). Damping values change under global Jacobian scaling; [linear/L; angular] would require correspondingly rescaled lambda. Tracking CSV singular indicators refer to weighted -de/dq; the unconstrained sweep and search refer to weighted raw body J. These matrices agree at zero residual but need not agree away from it.

For each declared seed, search exactly 20000 configurations with explicit mt19937 integer mapping and 2% joint-limit margin. Record all sigma_min/condition/q and contact eligibility. The contact-free subset (no negative contact distance in mj_forward) is sorted by weighted body-Jacobian sigma_min. Select its 0.1% quantile as near-singular and median as nominal. No selected pose is hand-edited. This initial contact screen is not online collision avoidance or dynamic collision validation. The 101-point straight joint-space interpolation between selected poses is an unconstrained differential algebra sweep, not an executed path. At each point use a 0.01 norm scaled twist along the smallest left-singular direction; record actual twist, requested dq, rank, damping and task residual.

Executed paths are separate simple feasible joint-space reference excursions, converted to TCP SE3. q_ref=q_start+(1-cos(2*pi*t/4))/2*amplitude; signs come from seed+77 and amplitudes are 0.04rad nominal/0.01rad near, reduced only by a shared bound margin rule. After 4s, hold for 2s. Initialize the plant identically and hold q_start for 1s warmup. Reference velocities are analytic. These paths establish basic baseline execution, not CAD-following, predictive control, retiming, null-space behavior or collision avoidance.

The same adapter integrates a persistent joint target, clamps requested velocity componentwise using official per-joint limits, then clamps targets to the common position range. Accepted velocity is the actual target increment divided by dt. Plant q/dq are recorded separately; this target guard does not certify physical joint-speed bounds, acceleration, jerk or hardware safety. Every executed sample includes raw request, accepted dq/q target, before and after q, executed dq, reference q, desired body twist, residual, TCP pose and physical errors. Measured limit violations are separately counted; interventions are not silently attributed to a method's raw algebra.

Development seeds 1101/1102 and held-out seeds 2101/2102 are separate. Fixed and adaptive methods each evaluate five damping candidates on both nominal/near cases for both development seeds (20 trials each); MP uses the same four development scenarios. Frozen selection objective is mean(position error)+0.3*mean(rotation error)+0.001*mean(accepted dq norm)+0.01*intervention fraction+100*failure indicator. Select minimum mean objective per method, ties favor the first (smallest) candidate. Candidates/objective/tolerances are saved and hashed before development; selected settings are saved/hashed before evaluation. Evaluation loads those settings and requires the original design hash. No held-out retuning is permitted.

Completion criteria were frozen at final position <=0.01m, final geodesic rotation <=0.05rad, peak position <=0.05m, peak rotation <=0.2rad, and full simulated duration without numerical failure. These are development execution tolerances, not research-performance thresholds. Preserve failure codes and raw outcomes even when a method completes with bounded commands. Phase 3 requires independent root review of the Phase 2 gate.

Any measured position/velocity violation classifies EXECUTED_LIMIT_VIOLATION regardless of acceptable TCP error. Controller, solver and plant exceptions retain a trial failure code and error file; initialization failures retain a summary row. Output streams throw on write/flush failure rather than declaring incomplete evidence successful. Search fractions/counts, finite positive scaling/durations, period-aligned duration, damping candidates and disjoint seeds are validated before numerical loops.

The executed reference is derived from a feasible joint path and may suppress excitation of the weakest singular direction. Its completion does not show MP speed spikes during executed tracking or DLS superiority. The worst-direction differential sweep is a separate algebraic stress case. These original Menagerie plant trials must later be repeated consistently for all baselines on the integrated tool/fixture plant; Phase 2 does not claim CAD/payload validation.

## Supplementary dynamic weak-direction diagnostic

After the original evaluation, the acceptance review requested a separate diagnostic. Its design was frozen before execution: seeds 3101/3102, the same contact-free quantile selection, same original chosen damping, same 4ms plant/guard, 4s smooth closed excursion plus 2s hold. At selected q0, take the weakest left singular vector of [linear;0.3*angular] J. Undo the angular scale to obtain fixed body generator ξ. Define Td(t)=T0*exp6(ξ*a(t)), a(t)=0.002*(1-cos(2*pi*t/4))/2, and desired body twist ξ*a_dot. Files config/phase2_weak.yaml and results/phase2/frozen_weak_design.yaml record this supplement; the original design, tuning and evaluation remain unchanged. run_weak.sh verifies original design/selection hashes and saves the supplemental freeze/hash before running. This diagnostic does not retune either damping and is excluded from the original evaluation aggregates.

This Cartesian diagnostic reference is not pre-certified feasible. reference_q columns in weak diagnostic CSV contain the starting joint anchor, not an inverse solution or a feasibility certificate. Actual desired TCP pose/twist and exact generator are recorded. Dynamic failure can reflect controller/plant/guard interaction and reference feasibility; it is not an algorithm-only or general research superiority claim. A process return code of zero means complete data generation, not that every trial passed; inspect trial codes, summary.json and review. Adversarial runner-contract probes are stored under diagnostics/, separate from scientific trial aggregates.

`run.sh` regenerates the primary development/evaluation, then the supplementary diagnostic, fault-contract probes, installed consumer, pure-math tests, offline CSV audit and figures. Original raw records are canonical in development/, evaluation/, weak_direction/. Repeated evaluations only verify unchanged behavior after failure-policy fixes and are not additional independent seeds/trials. Offline Python scripts validate/provide figures and do not implement control or plant stepping.

The original cached-site pose observations were later found to lag post-step q and were preserved as historical evidence. Current canonical aligned observations are in `results/phase2-observation-sync/{development,evaluation,weak_direction}`; see `reviews/phase_2_review.md` for the independent correction gate. The current runner uses a separate position-only observation workspace and leaves integration state unchanged. Reproduce the retained correction with `scripts/phase3/replay_phase2_observation.sh`. To plot it explicitly, run `python3 scripts/phase2/plot_evidence.py --input results/phase2-observation-sync/weak_direction --output results/phase2-observation-sync`; original pose plots must not be presented as corrected evidence.

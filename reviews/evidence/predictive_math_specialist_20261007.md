## Main finding: command/model acceleration has different meaning

The current adapter initializes physical state `(q,v)` from measured position/velocity, takes QP input `a`, requests `w_next=v+Δa`, and sends the persistent position target `c_next=c+Δw_next`, with Δ=0.004 s. Its forecast instead uses `q_next=q+Δv+0.5Δ²a`, `v_next=v+Δa`. Thus the sent position target differs from the physical forecast by `(c-q)+0.5Δ²a`, even before servo dynamics. The history patch correctly checks the derivatives of accepted `w`; it does not make `a` the physical acceleration of a position servo.

Let the prior accepted velocity be `w`. For an unprojected command, its actual command acceleration is `α=(w_next-w)/Δ=a+(v-w)/Δ`. Equivalently, `a-α=(w-v)/Δ`. Recomputed from all 139 complete path cycles of reference-tracking-v19-full, this identity holds to 1.11e-16 rad/s². The pre-command velocity mismatch reaches 0.003637355 rad/s, equivalent to 0.909339 rad/s² after division by Δ. Requested/model acceleration reaches 0.927021 rad/s², while recorded physical acceleration reaches 0.0789446 and command acceleration 0.0838113 rad/s². These maxima do not establish a uniform ratio; they establish that the quantities are not interchangeable.

The source-read FR3 model uses position actuators with kp/kv of 4500/450, 3500/350 and 2000/200, plus inertia, damping and friction. A measured-state velocity request is an input to this position servo through a target accumulator. It is not a low-level physical acceleration interface. The observed 4 ms position forecast discrepancy near 7.2e-6 rad is insufficient to validate the 0.8 s acceleration forecast: the direct position sensitivity scales as Δ², while later preview sensitivity scales as h². The current actual-state SCP/nonlinear validator checks geometry/pose on its kinematic forecast; it cannot repair this actuator contract merely by relinearizing geometry.

`scripts/phase5/servo_contract_reference.py` gives an exact synthetic counterexample for a scalar first-order position servo `q_dot=10(c-q)`, zero initial state, Δ=4 ms and constant a=1 for 0.4 s. Its current measured-state adapter yields q=0.0030883 and v=0.0147947, whereas the kinematic forecast yields q=0.08 and v=0.4. This is not identified FR3 dynamics or a robot result. It shows that the present contract fails even for a simple known position servo. The corresponding command-acceleration contract yields target c=0.0808, while physical q=0.0510253; retaining the explicit servo state correctly exposes that lag instead of replacing measured state by command state.

## Smallest coherent correction within the shared plant

Prefer **command acceleration α** as the control input, keeping both the measured physical state `(q,v)` and command history `(c,w)` explicit. Do not silently substitute accepted velocity for measured velocity. Preserve the existing shared position-target integration for fairness:

```
w[l+1] = w[l] + Δ α[k]
c[l+1] = c[l] + Δ w[l+1]
physical_state[l+1] = ΦΔ(physical_state[l], c[l+1])
```

Here Φ is a validated position-servo transition model, including the held target and the existing 2 ms physics substeps; no new optimized torque input is needed. A local affine model `y_next=A_p y+B_p c_next+d`, y=(q,v), is a possible development approximation, but its prediction error must be measured on separate development traces and bounded/monitored. Each 40 ms preview cell must compose ten actual 4 ms target updates. For constant α and h=mΔ, the exact target formula is `w_next=w+hα`, `c_next=c+h w+0.5(h²+hΔ)α`; using `0.5h²α` alone changes the present target integrator. An arbitrary/nonuniform mesh needs full Δ steps plus an explicitly defined final fractional update.

Physical `(q,v)` remain initialized from measurements. Command `(c,w)` remain initialized from accepted history. α and its first jerk use previous **accepted command acceleration**. The old `previous_model_acceleration=(w_next-v)/Δ` is no longer the correct α history. Warm starts shift α by actual elapsed time and reconstruct both command and physical trajectories from these separate initial conditions. Projection updates accepted α; a changed physical-model residual is recorded separately.

Task tracking, posture, collision and singularity costs/constraints must use predicted physical q; physical velocity limits use predicted v. Command position/velocity/acceleration/jerk limits use c,w,α. Physical acceleration/jerk require the servo model or independent executed checks, and cannot inherit command α limits. The terminal condition must distinguish stopped command w=0 from predicted physical v=0 and preserved progress continuation. Command states can be eliminated as affine functions of α, avoiding an automatic increase in QP decision dimension; this is no claim that timing will improve. Retain original SI-row acceptance, native SOLVED-only, current-command age guard and nonlinear checks.

A kinematic desired-motion forecast is another coherent contract only if a justified low-level velocity/acceleration realization makes the physical forecast track it. Changing the common plant to achieve that would be a separate all-method development epoch, not this audit's smallest correction. Neither approach is accepted until meaningful progress and actual executed 10 mm accuracy are observed.

The accepted high-Q model itself is inconsistent in usefulness across feedback ticks: terminal position error is 0.640762 mm at tick500, 10.6205 mm at tick550 and 11.5953 mm at tick570, while terminal s is essentially zero at the latter two. At tick638 it predicts s_N=0.0249712 and terminal error 0.629944 mm, shortly before solver failure. These are forecasts, not actual future trajectories; later replanning changes controls. They motivate fixing the command/plant contract before interpreting waiting solely as an objective defect.

The original linear reward `-w_p s_N` and quadratic terminal progress cost care about how far progress gets by horizon end, with no direct preference for when it occurs. The optional exact discounted integral `-w_p ∫exp(-t/τ)r(t)dt` is mathematically legitimate: for a cell, A=τ(1-exp(-h/τ)), B=τ²(1-(1+h/τ)exp(-h/τ)), giving exp(-t_k/τ)(A r_k+B b_k). Its τ→∞ limit differs from `s_N` only by the constant initial s. It rewards early progress, preserves the feasible set, and introduces no hard minimum speed. It does not ensure liveness or remedy plant-model mismatch; the unchanged terminal progress cost can still dominate it. Treat τ/weight as a fresh development protocol and preserve failed epochs.

## Actors and actual observation points

A future reviewed parent executable owns a private one-attempt ProcessObservation
before artifacts, pipes or fork. Child has a different private owner/ledger.
Every fact carries actor, declared/dispatch/OS-observed class, known flag, actual
stage and prefix coverage. A matching caller file/hash/record is not an observer.

| Fact | Actual production and retained owner |
|---|---|
| argv | Review declares recipe. Parent owns bounded exact byte strings/pointer roster before dispatch; immutable syscall-supplied argv is Dispatch evidence. Child startup argv and an optional actual proc snapshot are separately labeled observations. No decoding/normalizing logs into argv; an expected recipe is not kernel observation. |
| exec | Parent opens/hashes pinned executable FD and records requested path/FD identity. Actual fork return records child-created PID or errno. argv[0] never establishes executable identity. Child pre-exec failure writes bounded stage/return/errno to the private error pipe. Parent verifies live post-exec kernel exe FD identity against the sealed executable and a same-session startup message before arming Model. |
| cwd | Requested path differs from parent actual directory FD identity, child's actual fchdir return, and parent post-exec kernel cwd observation. A rename/deleted path can make text missing without inventing a directory identity. |
| spawn/exec failure | No PID is known on failed fork. Error-channel bytes must actually be read, complete and source-bound before typed decoding. Error-pipe EOF alone is ambiguous: child may die before reporting, so it never means exec-success by itself. |
| stdout/stderr | Parent multiplexes both actual pipe reads into separate FIRST raw-byte files. Each keeps received, stored and independently read prefix counts/SHA coverage, syscall/EOF/fsync/close facts. Full stream requires real EOF plus complete persisted/readback bytes; actual empty stream is distinct from unopened/missing stream. |
| termination | Parent alone owns actual terminal waitpid result for its unreaped child: raw status, WIFEXITED/code or WIFSIGNALED/signal and conditional core flag. Wait errors, stop/continue and termination requests do not become exit0 or normal exit. |

A minimal future lifecycle is: reviewed admission -> private parent owner/FDs ->
one fork/descriptor-bound exec -> observed startup barrier -> separately permitted
component -> parent drains logs and observes wait -> parent terminal envelope.
This is a finite component proposal, not permission to build or run a general
runner/main. Post-fork pre-exec work is only a separately reviewed, preallocated
async-signal-safe descriptor/exec/error path; no inherited C++ SharedCaseBudget,
heap/EVP/SDK callbacks are used there. An EOF without a verified live startup
observation leaves exec unknown, even if later wait reports an exit.

Child cannot know its future observed terminal exit, parent wait result, final
pipe EOF, completed parent log files or later parent publication. Its requested
exit/application return and provisional manifest remain child-local facts. Parent
wait and completed logs belong in a separate later parent terminal envelope;
never patch an earlier child manifest to pretend it knew them.

## Private cross-process binding and closure

The parent privately creates anonymous error/start/arm and stdout/stderr channels,
records real endpoints/closures and returned child PID, and retains the sealed
executable/cwd FDs. It closes unused ends; future reviewed child has no descendants
or unrelated writers. A reviewed child-entry startup barrier and actual kernel
exe/cwd observations must match those identities before Model authorization.
If child dies before that check, logs/wait may be real while executed-image binding
is missing. Actual inherited FD messages are reports from that actor, not an
arbitrary file+SHA success certificate. Both binaries/source closures and this
handshake require new separate review, not reuse of the current Model review.

A reviewed attempt ID labels the relationship; it is not authority by itself.
Parent owner, actual channel/PID/exe observations and child local producer
verification supply the binding. Parent independently reads the child's actual
claim/provisional artifacts by safe FD and retains identity/bytes/physical SHA;
compare actual claim inode/path/pins and same-session child reporting, not just a
claim digest that can repeat for identical inputs. V4 claim alone contains no
parent-session binding. A later child protocol/handshake and private bridge are
required; legacy V4 cannot silently acquire that meaning.

Current child manifests and artifact hashes do not mint genuine in-process Model
or capture owners. Parent-observed process/log/FD facts, child-local private
component facts and reviewed expected declarations remain distinct. Complete
child registry/readback/reconstruction, parent terminal-envelope readback and
cross-artifact failure closure must be independently reviewed before root READY.
That publisher/whole reader is neither designed in detail nor implemented here.

## Budget boundary and failure retention

PARENT_BUDGET_CANDIDATE.json defines only a conservative integer candidate.
Parent and child are different processes: equal inherited addresses/IDs never
mean sameCase or shared live counters. Parent and child own separate real ledgers
before their materializations, bound through the private launch session and
reviewed cap descriptors. A later coordinator must enforce aggregate live,
charges, metadata and unique-output bounds under the unchanged original caps.
Kernel pipe storage counts once in the parent reservation; inherited parent
userspace counts conservatively again in a child pre-exec transient allowance.
After exec the child constructs a fresh local bootstrap ledger and then its
reviewed component ledger. Existing unmetered bootstrap/parser/provider/RSS
obligations are still blockers, not retroactively covered by this candidate.

Actual pipe capacities are observed before fork; any exceeding the reviewed
candidate refuses rather than enlarging a cap. Rings, descriptors, argument
copies, metadata, hash/close/error work and spool output must be reserved before
use. Both pipes must drain while waiting; sequential blocking drain is forbidden.
Caps/deadlines can reject incomplete logs. Retain actual prefix plus a bounded
overflow observation, apply only a separately reviewed terminate/reap policy,
and mark remaining bytes missing. Never truncate, drop/normalize bytes silently,
retry a spawn or assert complete logs after loss. Failed/partial files stay FIRST.
Signal-request return and actual terminal wait status are separate observations.

Raw logs stay immutable retained evidence under docs/backup.md; completed hashes
and verified storage copies enter the small checkpoint. A process exit0 with
missing log/identity/child closure is not component or phase acceptance.

## Missing owners and smallest later bridge

Before fork/admission failure: no child, no child logs/exit/claim/output owner.
After fork but before observed exec: child-created/wait/pipe bytes may exist;
child producer, grammar, Case, claim and Model owner may all be missing.
First grammar/hash/open failure before ForecastReleaseState: current child has
no genuine full capture owner. Parent logs/exit cannot manufacture one or infer a
constructor attempt from text. An actual V4 claim failure may retain private
prefix/status in the release, but current public early-failure publication is
absent. Constructor failure may retain an actual OpenOutcome attempt flag, not a
successful forecast or default empty result.

The smallest later child bridge is a new private entry/bootstrap failure owner
created before first grammar/open, holding bounded actual stage/error/known
fields. It may attach only genuinely existing release/context/claim/OpenOutcome
objects through private source factories, and emit a source-empty failure type
when none exists. It must not synthesize numeric arrays, claim identity or a
successful forecast. This is a separate source dispatch/review, not current work.
FILE_PLAN_AND_GATES.json lists the minimal proposed boundaries. Parent/child
closure, public early publication, complete failure archives and root READY stay
explicitly pending. No plant/main/scorer or rejected seed91013protocol1 is released.

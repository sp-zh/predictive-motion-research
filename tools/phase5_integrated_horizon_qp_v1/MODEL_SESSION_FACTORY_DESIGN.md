# Minimal additional Model authority required, design only

No new factory, constructor loop or runtime is implemented here. Existing
ReviewedForecastPermission/OwnedLiveInvocation/PinnedModelHandle/
OwnedPublicForecast remain private, genuine and single-use, without changed
production friends or archived carrier casts. V1-V4 latch one prepare/open/
wrapper constructor/metadata/nominal extension rollout. These deliberate wrapper
entries are not complete Pinocchio/native sub-constructor or SDK/getter totals.

The first component can legally use that existing one nominal release, including
unchanged frozen invocation/cost/profile/readset and attempt claim, then the new
pure adapter. Its output cannot be validated with another rollout on that release.
Creating a new permission file, using another process, refreshing a claim path,
reconstructing Model or copying archived raw data does not release a candidate
forward or a new cycle. Old release/schema/counters must remain immutable.

## Smallest next versioned factory for one candidate forward

A new source/profile-reviewed session boundary is needed, with one external
review token bound to the actual final program, source closure, SDK/config/units,
actual completed observation/history boundary, fixed timing mode, exact N20 mesh,
inline task/objective/constraints and output/resource limits. It should own one
immutable session claim and a ledger with explicit forecast roles:

- NominalDerivative: one full extension value/maps attempt from actual initial
  and predeclared nominal controls. Return original success/failure prefix.
- CandidateValueValidation: at most one independent full physical/command/
  progress forward from the SAME actual initial using the exact solved candidate
  controls. It is not teacher forcing with nominal states and not evaluation of
  the affine surrogate. No new derivative is required for simple feasibility
  validation; if desired, that is a separate explicit role/counter.
- PlantCommit: none for this first session. Actual plant commands/steps/observer
  and supervisor/stop need their own reviewed transaction protocol.

Attempt latches precede profile rechecks/allocation/native entry. Constructor,
metadata, nominal rollout, candidate forward, source callback/query and solver
counters have separate role identities and failure state. No admission failure
is retried. Retain exact raw values, contact/friction/force/control clip facts,
unsupported prefix and full original first error. No shorter forecast is returned
as success. Root must decide an explicit pinned owner for candidate value
simulation: a separately reviewed value Model owner or a narrowly added method
on a new versioned session. Existing private fields/methods must not be accessed
through friend redefinition, linkage tricks or a reopened V1-V4 release.

Because existing normalization only accepts genuine OwnedPublicForecast whose
factory is private, a future V5 boundary must be a complete versioned target
fork with reviewed ownership/type invariants and normalization integration, or
an explicitly reviewed minimal bridge in that new target. It cannot reuse the
old namespace's private ForecastFactory definition in another translation unit
(ODR violation), fabricate the old owner or mutate the preserved old source.
The design is a concrete dependency, not source already implemented or permission.

## Session for750 task commits after first-cycle validation

A later separately released session would pin the same immutable model/profile
and task data, and cap750 task cycles, one nominal plus one candidate role per
cycle, one solver attempt per iteration and predeclared relinearization count.
The smallest functional version has no SCP relinearization: one nominal and one
candidate check; failure stops. SCP3 would require up to3 nominal/candidate roles
and3 QP attempts per cycle explicitly; it is not implied by the old config.
A role must be associated with cycle ID, independently completed observation ID,
transaction ID, actual q/v, accepted C/w, accepted alpha/b history, nominal/candidate
control digest, mesh, exact elapsed timing and returned raw provenance. The
candidate from cycle i can never authorize cycle i+1 or update history early.

Model/metadata reuse is explicit session scope, not automatic release renewal.
Freeze deliberate constructor/metadata counts for each actually chosen native
owner. Do not claim one wrapper constructor means all internal native constructors
are one. Preserve every cycle/attempt, including failures and abandoned plans.
Warm shift controls are only a guess; every nominal/candidate is repropagated from
fresh actual state. Never integrate the previous prediction as next measured state.
After independently validated candidate and fresh plant commit eligibility,
commit exactly C_next/w_next; update history only from completed actual acceptance.
If command acceptance differs, retain original candidate/response and stop this
path rather than silently projecting or relabeling physical acceleration.

The session needs an explicit lifetime and cumulative ledger for the WHOLE task,
including model/solver reuse, raw result retention/copies and output limits. Old
BatchBudget's cumulative limits and per-forecast375-cycle ceiling cannot be
reset per iteration and then called a proved750-cycle budget. A new ledger/source
policy must be reviewed before a repeated session. Finite controlled pool/matrix
limits may be sufficient for a functional diagnostic without a universal OS RSS
or full Parent proof; all native overhead/RSS claims remain separately qualified.
Warmup and physical stop/settle are separately declared, outside3-second task time.

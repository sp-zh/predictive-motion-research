# Borrow, original producer and bounded per-leaf export contract

Session originalConsumer uses the already reviewed B1 private original gate.
CostFactory original scope, actual cost-origin token, same stable source and
SAME private partition are checked on entry. Live UsedTerm/CostEvaluation pointers
exist only in the genuine callback; they clear on every success/exception. Later
replay cannot enter this phase. No scalar getter/provider is exposed as a saved
IO closure; private NumericLeafView generation checks enforce synchronous reads.
The source/context/cost stays owned by the producer during the original phase,
and by attached genuine inventory owner for stored leaves. Readonly historical
partition observer alone is insufficient.

Optional export requires current unrefused session and actual applied, unrefused,
same-source/same-case partition plus SAME live affine/cost owner (or actual original
producer). It checks receipt_attempts < private receipt_limit BEFORE creating the
next file; failed attempts count conservatively, and no retry/field trimming can
get full success. The normal writer/reader/record tickets allocate from actual
unallocated headroom; credit does not suppress actual budget checks or raise caps.

A bounded receipt slot is allocated before IO, retaining every written/failed
provisional result in the session. Generated role name binds actual role/primary/
secondary to its receipt; scalar shape/type comes from private genuine leaf. A
writer result is not accepted until independent readback parses its actual FD and
compares EACH scalar kind and exact bits with the SAME held getter, preserving
signed zero and failure IEEE payloads. No new mathematics or matrix snapshot is
recomputed to make a reference. File SHA/count alone is insufficient. Root READY,
full role coverage and duplicates/full metadata still require B2B2 closure.

Bound metadata has a20-slot frame/reuse charge; no whole numeric array copied.
WriterIO20, reader28, record axes4, source normalizer640/input16 and original math
remain under actual case/batch/live/cumulative/output/metadata hard limits.
Formatting bounded generated role metadata charges additional scratch. Retained
receipt strings have bounded logical payload cap; STL/vector capacity/process RAM
is not instrumented. Future full manifest actual metadata bytes and per-role
coverage must be counted explicitly, not inferred from this cap. Caller callbacks
must borrow reviewed owners, not allocate unbudgeted numeric caches or run Model/
IO in copy constructors or asynchronously. C++ source freezes remain prerequisite.

Exception/reentry/closed/current-generation/semantic mismatch poisons this capture
session, preserves FIRST refusal, source tree and failed files, and prevents full
success even if nested refusal is swallowed. Session mathematical source may
remain valid independently; closing is explicit and does not publish success.
Forensic defined reading supports failed source spans, but complete export still
requires the live nonrefused private partition; failure recording/archival variants
beyond this finite core remain pending. No uninitialized/unused memory is output.

## Final failure and paired-record closure

attachReturnedSource deliberately skips the healthy-capture precondition on the
FIRST nonactive attachment. Even if original IO/sink already refused, it consumes
and retains the actual returned failed source (including partial CostStorage) and
original gate evidence, without clearing the first refusal or replacing an old
owner. Active/repeated attachments reject. All role/guard/reserve/unsupported/
frontier/close/issuance paths latch capture errors; a swallowed nested refusal
causes the enclosing callback/traversal to fail health checks.

Every private move-only BoundLeafAttempt holds actual role/key/original-or-stored
scope/source-origin/cost-origin/partition plus WriteOutcome and optional ReadOutcome.
Readback success AND failure stage/byte/consumed/bit/hash frontiers survive.
Semantic comparison records index/actual bits/expected-valid bits and mismatch;
there is no comparison-array copy. The actual shape exists in the retained write
receipt and has ONE persistent4-axis ticket. A pre-IO expected snapshot survives
low-level pre-admission failure; a valid returned writer receipt REPLACES it.
The temporary writer-returned4-axis snapshot is separately ticketed, transient
within the writer20-versus-reader28 headroom; it does not create a second persistent
receipt. Source/capture flags stay independent and no full coverage is minted.

Supported stored keys are validated BEFORE binding: globals0/0; cell/cycle/substep,
boundary and term index/0; native map group0..2/map index; cell control typed split
0 or1; addition term/actual addition index. Invalid keys refuse, never silently
canonicalize caller data. Original keys derive only from actual callback views.
Paired metadata cannot be caller-constructed or copied as a coverage certificate.
Duplicate required-role/coverage/actual full manifest checks are still B2B2.

## Readonly failed-owner forensics

withDefinedRegions is a DISTINCT read-only forensic borrow. It may inspect actual
held C1 defined spans/frontiers after capture refusal or explicit close, without
clearing/restoring capture status. It has its own active generation, first-forensic-
error latch and scalar/index/reentry checks. The original first source/capture
reason remains unchanged. No array32 trace copy or public trace pointer escapes.
Only exact defined values and one-at-a-time frontier counters are readable.

Every such leaf reports readOnlyForensic=true; the private export adapter rejects
it regardless of applied history/capture health. No IO retry, normal leaf success,
verified-file increment, root READY or full-capture acceptance follows. An error
in forensic visitor/index/reentry poisons only this forensic sequence's first
latch; original rejected capture is not mistaken for restored health. Owner must
remain genuinely held/attached. Existing C1 region callback error semantics still
retain/poison their own outcome as defined there; no source failure is erased.

Generation checks apply ONLY while the borrowed C++ object itself is still alive. Saving its pointer/reference and calling after object destruction is undefined C++ misuse, not safely detected by this API; the frozen trusted callback contract prohibits it. Logical payload tickets do not cover all allocator/STL/SDK/process RSS.

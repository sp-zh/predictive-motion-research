# Actual MoveIt Servo baseline

This baseline calls installed `moveit_servo::Servo::getNextJointState` in a separate executable/PID. It is not a local Jacobian imitation. Installed Jazzy `ros-jazzy-moveit-servo=2.12.4-1noble.20260905.075156` and actual dependency versions are recorded in `results/phase4/installed-debs.txt`. Official 2.12.4 source tag commit `1ade0e9dcf50dbbbc3a984b995c786cf12736235` was consulted to interpret API behavior; this does not assert that an entire distribution binary equals that Git tree.

The generated arm-only SRDF group runs from fr3_link0 to inspection_tcp, including the full tool with no ghost hand. The actual KDL plugin is loaded. The model uses common Menagerie hull collisions, full true tool primitives, all channel boxes and the proven enclosing floor box. The intrinsic collision checker, singularity checks and Butterworth smoothing remain enabled. Parameters are recorded in config/phase4.yaml: publish period4ms, speed_units, collision250Hz, self proximity10mm, scene proximity20mm, singularity slowdown17 and halt30, joint margin5mrad. Linear/angular request caps0.4m/s and0.8rad/s also apply to other methods. No integrated-result parameter search weakens these thresholds.

Measured q and dq arrive through a local ROS JointState publisher/current-state monitor and are independently placed in the locked PlanningScene. Cartesian commands use the actual synchronous C++ API via a pipe, in physical world-frame units; no ROS Cartesian transport cost is claimed. CSM q/dq matching is checked before each call. The real collision thread is asynchronous. A CSM match does not prove which state its most recent collision cycle used; the common external measured-state geometry supervisor independently validates acceptance. An early 8ms diagnostic sleep was removed because it was not a freshness proof and would distort timing comparisons. Its output is preserved only as development history.

The installed Butterworth filter must be reset to the initial measured q/dq and zero acceleration. Without reset, its zero-history transient produced a large target change despite zero velocity; those outputs were rejected and preserved. Each final trial starts the real Servo process before the common2s plant warmup, validates an exact zero-request target/velocity contract, then excludes setup cost from task-cycle measurements. All methods have the same plant warmup and initial conditions. No smoothing is disabled.

Returned position target, native velocity, shared-adapter requested velocity and accepted command are separate. Smoothing means the returned target difference can differ from native velocity. HALT/INVALID/JOINT_BOUND requests enter the same bounded stopping policy as other methods, so a stop status cannot silently issue a large target jump. On this integrated curve the native safety halt is a valid negative result, not evidence of task completion.

Actual API-only seconds, state synchronization plus API seconds and parent-pipe roundtrip seconds are all recorded. Primary method timing includes the real adapter roundtrip, not just the solver call. The host/pipe/ROS observation path is not a4ms real-time guarantee. A separately selected collision-free, well-conditioned state exercises nonzero native motion with unchanged safety thresholds; the integrated path's stops and all failed development attempts are kept.

Reproduction after Phase0–3 setup: `scripts/phase4/build.sh` builds the math/controller context and the separate Servo context; `scripts/phase4/run.sh RAW_OUTPUT_ROOT FRESH_EPOCH` executes frozen development then untouched evaluation seeds. The native executable protocol is one line containing sequence,7 measured q,7 measured dq and6 world twist components; RESULT returns sequence, PID, status, CSM match, API/adapter timings,7 target positions and7 native velocities. The initializer uses a nonnegative sequence because the sidecar protocol uses uint64.

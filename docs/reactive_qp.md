# Reactive constrained differential IK: Phase 4 component

The library is model independent. It accepts Eigen matrices, external measured-state ages, external collision gradients and caller-specified limits. It does not contain a robot, ROS, MuJoCo state, scene, future plant rollout or manipulability maximizer. `BUILD_REACTIVE_QP=ON` adds the installed `predictive_motion_control::reactive_qp` target; the existing Eigen-only IK target remains independently available.

The frozen diagnostic minimizes `0.5*||W(J*dq-v)||^2 + 0.5*ridge*||dq||^2`. The task rows are body linear velocity in m/s followed by angular velocity in rad/s, with angular rows multiplied by a 0.3m length. `ridge=9e-6` is the Hessian regularizer; its square root is the previously selected 0.003 DLS damping. Ridge has units `(m/rad)^2` in this weighted objective. Common baseline projection and stopping instead minimize joint velocity error in `(rad/s)^2`. A nonlinear manipulability objective is not made convex merely by placing it in a QP; no manipulability guarantee is claimed here.

The external common adapter intersects URDF/MuJoCo/actuator position ranges, position margins, official URDF velocities, command acceleration and command jerk. It applies the one-step position bounds both to measured q and persistent accepted position targets. Command acceleration and jerk are finite differences of accepted command velocity at 4ms. Executed velocity, acceleration and jerk are separately observed at every 2ms physics step. Limits on position-target rate do not bound the physical actuator response. Acceleration and jerk limits are declared simulation assumptions, not manufacturer specifications.

Collision velocity dampers use `grad(d)*dq >= -eta*(d-safe)`, distance in m and eta in 1/s. Every potentially active cover sphere has a separate row; no derivative of a minimum is substituted. Unmodified native MP/fixed/adaptive requests are recorded, then passed through the same constrained velocity projection and nonlinear checks. These are supervised baselines. The QP directly optimizes its Cartesian tracking objective under the same constraints. Requested, native and accepted outputs remain separate in raw data.

OSQP is exactly 1.0.0, commit `236713ce9a56c182ac3230d52108f952afce1523`, QDLDL `138fdac58b9cd1c4137ff1b99152c8108a6cff5b`. The build is Release, builtin algebra, double, int32, static, profiling enabled, printing/interrupt/codegen/demos/tests disabled. Exact cache flags and archive hash are in `results/phase4/osqp-build.json`; production and installed-consumer runtime checks reject any other version. Each request performs a fresh setup with warm starting disabled. Setup and solve costs are included. The external Servo build is a different CMake project and PID because its OSQP vendor can otherwise overwrite a same-named imported target even when executables are separate.

Only exact `SOLVED` results with finite solution/residuals and independently checked `A*x` bounds contain a usable command. The default acceptance tolerance is 1e-6 in each row's units, separately rad/s for joint rows and m/s for distance rows. Inaccurate, iteration/time limit, stale state, primal/dual infeasibility, nonconvex input, invalid input, setup/API failure and constraint violation remain distinct failures. A stable normalized Hessian check rejects finite-input overflow counterexamples. Objective and damper/bound builder overflow is explicit.

Failure requests a constrained minimum-velocity stop. The adapter preserves command acceleration/jerk/position and collision constraints. If no fresh, feasible, nonlinearly checked stop command exists, the simulation terminates without issuing a zero or silently reusing the previous command. A terminated simulation can still have nonzero measured velocity; this is not a hardware emergency-stop guarantee. Raw `substep=0` termination rows show the last accepted history and explicitly state that no new command was issued.

The diagnostic runs virtual 4ms control / 2ms physics. Complete computation age is checked before committing, including nonlinear checks and prior logging delay; the host is not a real-time system. Geometry, primary API/IK, assembly, proposal-QP setup/solve, stop-QP status, nonlinear validation, observer and complete state age are recorded separately. Deadline failures and all negative results must be included in reports.
